## 1. Technical Disclosure Scope & Claim Formulation (`ZC-CORE-008`)

To establish effective documentary prior art that anticipates third-party patent attempts, the disclosure must satisfy the legal standard of **technical enablement** (i.e., teaching a person having ordinary skill in the art how to make and use the invention without undue experimentation).

The disclosure is drafted in patent-claim style under four distinct inventive aspects:

### 1.1 Inventive Aspect 1: 3-Layer Inbound SPI Flash Firewall (`zc_spi_flash_firewall.sv`)
* **Claim-Style Technical Formulation:**  
  A synchronous hardware SPI bus firewall disposed between an untrusted external network master controller and a shared multi-bank SPI Flash memory device, comprising:
  1. *Layer 1 (Status Reconciliation Circuit):* An internal hardware finite state machine (FSM) that monitors inbound SPI command opcodes and MISO status register bytes; wherein upon detecting a write command (such as `02h` Page Program or `06h` Write Enable), the FSM transitions to an unsynchronized reset state (`UPD_UNSYNC_RESET`) and withholds the active-low effective Chip Select (`cs_n_flash_eff_o = 1'b1`) until an authenticated `05h` Read Status Register (RDSR1) transaction verifies that both the Write-In-Progress (WIP) and Write-Enable-Latch (WEL) status bits are simultaneously zero (`SR1[1:0] == 2'b00`).
  2. *Layer 2 (Frame Strobe & Electrical Fault Gating):* Logic circuitry that enforces frame completion strictly on the rising edge of Chip Select (`cs_n_to_iso_i`) while the serial clock is inactive (`sck_to_iso_i == 1'b0`); and an electrical fault input (`fault_high_sec_i`) from a secondary supervisor that unconditionally deselects the physical Flash memory (`cs_n_flash_eff_o = cs_n_to_iso_o | fault_high_sec_i`).
  3. *Layer 3 (Independent Boot Authorization Gate):* A dedicated hardware authorization output (`bank_b_commit_ready_o`) generated by the logical conjunction:
     $$\text{bank\_b\_commit\_ready\_o} = \text{spi\_idle\_ready\_o} \land \text{rom\_img\_verif\_valid\_i}$$
     whereby commit authorization to boot from the updated Flash memory bank (Bank B) is physically locked unless both SPI idle readiness and an independent external Boot ROM cryptographic signature verification signal are simultaneously asserted.

### 1.2 Inventive Aspect 2: OBI Subordinate Decoupling Bridge with Synthetic Error Trap (`zc_obi_subordinate_bridge.sv`)
* **Claim-Style Technical Formulation:**  
  A point-to-point Open Bus Interface (OBI) subordinate bridge circuit for isolating a trusted processing host CPU from untrusted or hung peripheral subordinates, comprising:
  1. *Synchronous Transaction Decoupling:* Independent host-facing and peripheral-facing request/grant handshakes that decouple CPU transaction pipelines from peripheral stalling.
  2. *Monotonic Watchdog & Orphan Response Absorption:* An internal 10-bit monotonic counter tracking peripheral latency; wherein if a peripheral fails to return a response (`periph_phys_rvalid_i`) within exactly 1,024 clock cycles, the bridge asserts a fatal fault interrupt (`subsys_fatal_fault_irq_o`), transitions to a deadlock state (`ST_TIMEOUT_ERR` / `ST_TRAP`), and continuously drains late-arriving orphan peripheral responses without forwarding them to the host CPU bus.
  3. *Deterministic Synthetic Error Trapping:* Circuitry that, upon detecting subordinate deadlock, terminates the pending host bus transaction in a single clock cycle by returning a synthetic error indication (`host_err_o = 1'b1`, `host_rvalid_o = 1'b1`) accompanied by deterministically zeroed read data (`host_rdata_o = 32'h0000_0000`), thereby preventing bus hangs while ensuring zero data leakage.
  4. *Warm-Reset Request Clamping:* Logic gating that forces host request grants (`host_req_ready_o`) and peripheral physical requests (`periph_phys_req_o`) to zero whenever the warm system reset (`rst_sys_ni`) is asserted, preventing glitch-induced bus contention during CPU reboot.

### 1.3 Inventive Aspect 3: Always-On Anti-Rollback Controller with 4-Phase Handshake (`zc_aon_post_auth_ctrl.sv`)
* **Claim-Style Technical Formulation:**  
  An Always-On (AON) hardware post-authorization controller for managing non-volatile One-Time-Programmable (OTP) eFuse memory, comprising:
  1. *4-Phase DAI Handshake Protocol:* A state machine interfacing with an OTP Direct Access Interface (DAI) enforcing the strict causal sequence: Phase 1 Address/Command Setup $\rightarrow$ Phase 2 Strobe Issuance $\rightarrow$ Phase 3 Macro Programming $\rightarrow$ Phase 4 Post-Programming Readback Verification.
  2. *Single-Cycle Grant Consumption:* Immediate, single-cycle deassertion of DAI write strobe authorizations upon acknowledgement, preventing multi-word burn-in race conditions.
  3. *Persistent Fatal Lock Across Warm Resets:* Dual-domain reset architecture wherein a fatal security lockout (`AUTH_LOCKED_FATAL`) triggered by voltage brown-out, clock glitching, or parity fault persists across warm system resets (`rst_sys_ni`) and can be cleared exclusively by a cold power-on reset (`rst_aon_por_ni`).
  4. *Monotonic Anti-Rollback Protection:* Hardware comparator verifying that requested Security Version Numbers (SVN) are strictly greater than or equal to the active OTP fuse value, preventing firmware downgrade attacks.
  5. *Hsiao (22,16) Code Parity Verification:* Hardware parity generation and checking implementing minimum Hamming distance $d_{\min} = 4$ SECDED protection across all OTP authorization codewords.

### 1.4 Inventive Aspect 4: Stratified Zero-Cloud Information-Flow Architecture
* **Claim-Style Technical Formulation:**  
  A system-on-chip architecture implementing two mutually exclusive hardware security profiles:
  - A first profile (STRICT) providing absolute physical unidirectional data diodes with zero telemetry egress; and
  - A second profile (HYBRID) employing the digital RTL firewalls of Aspects 1–3 to permit allowlisted, rate-limited semantic telemetry while physically prohibiting raw sensor data egress.
